# 老板遥控 Windows

Mac 把遥控器事件转发到 Linux 云端的说明在 [RELAY.md](RELAY.md)。那条链路只走本机回环，不代替下面的 Windows 蓝牙端口。

把 Apple Siri Remote 第 3 代（A2854）接到 Windows 上，当作触控板和快捷键键盘。

这是独立端口，不是把 Swift 逐行翻译过来。macOS 工程没有改行为。Windows 代码只在 `windows/`。

**没有在 Windows 电脑和这只遥控器上跑过。** 下面凡是依赖真机的项都标成未验证。单测只证明解析、手势和映射逻辑，不证明设备会发出这些字节。

## 计划

基准是仓库里的 macOS 原生 App（`app/`），不是根 README 里更早的 HyperVibe 用法说明。仓库没有 iOS 工程。

macOS 触控走私有框架 `MultitouchSupport`，按键走 IOHID，麦克风走 PacketLogger 加 CoreAudio 虚拟设备。这三样 Windows 都没有。端口改成：

1. 用 Win32 HID 打开 VID `0x004C`、PID `0x0315` 的接口，读真实输入报告。
2. 用报告描述符解析标准用法；描述符对不上时，再按公开记录的 A2854 原始报文解析。
3. 认不出的字节不产生触控、指针或按键。
4. 解析出的位移用 `SendInput` 注入光标、滚轮和键盘。这是输出，不是用假报告冒充遥控器。
5. 设置、映射、记录写到 `%AppData%\BossRemote\config.json`。
6. 界面是 WinForms，带托盘、连接诊断、电量和前台程序映射。
7. 语音单独调查。不移植 PacketLogger / CoreAudio，也不创建虚拟麦克风。

技术选择：.NET 8。可单测的逻辑在 `BossRemote.Core`（`net8.0`）。HID、`SendInput`、GATT 和界面在 `BossRemote.Windows`（`net8.0-windows10.0.19041.0`）。

## 语音：Windows 上能不能做

macOS 的做法是特权辅助进程抓 HCI，解析 ATT 里的 Opus，再送到 CoreAudio 虚拟输入。PacketLogger 和这套 HAL 都不在 Windows 上，不能把那段代码编译过来就说语音可用。

公开记录里，第 3 代遥控器的语音是 GATT 通知上的 100 字节包：序号、长度、以 `0xB8` 开头的 Opus。Linux 桥接还要先写未公开的 `F0 BC` / `F0 BB` 才会开始推流，而且 BlueZ 的 HID 插件会占住这些特征。Windows 的 HID 驱动同样可能不把它们暴露给普通 GATT 客户端。

这个端口只做了这些：

- 单测能从 100 字节包装里抽出 Opus 包。
- 打开「GATT 补充通道」时，如果系统允许，就订阅通知。
- 订到可解析的 Opus 时，诊断里计数，然后丢掉。
- 不写 `F0` 控制字节，不解码播放，不安装虚拟声卡。

所以按住 Siri 现在只会按住右 Ctrl。输入法要自己把「按住右 Ctrl」设成语音键，麦克风也要另选。遥控器麦此时没有接进系统。

## 安装

需要 64 位 Windows 10 或 Windows 11，以及 [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)（自己编译时）。运行自包含包不需要另外装运行时。

```powershell
cd windows
.\build.ps1
.\artifacts\win-x64\BossRemote.exe
```

`build.ps1` 会跑测试，再发布 `win-x64` 单文件。GitHub Actions 的 `windows` 工作流也会在 `windows-latest` 上发布并上传产物。这里没有创建 Release，也没有改仓库权限。

配置文件在：

```text
%AppData%\BossRemote\config.json
```

删掉这个文件会回到默认映射。

## 配对

1. 给遥控器充电。电量太低时它会像坏了一样没反应。
2. 拔掉 Apple TV 电源。Siri Remote 同时只连一台主机。
3. 打开 Windows「设置 → 蓝牙和设备 → 添加设备 → 蓝牙」。
4. 按住遥控器 **返回（‹）+ 音量 +** 约 5 秒，直到 Windows 里出现新设备。
5. 配对。名称可能是一串序列号，不一定写着 Siri Remote。
6. 打开老板遥控。连接页应出现「HID 已打开 A2854」。如果没有，点「重新检查连接」，看日志里的 Win32 错误。
7. 仍找不到时：按住 **TV + 音量 −** 约 5 秒重启遥控器，再配对一次。确认没有另一台电脑或 Apple TV 连着它。

程序不需要管理员。它以当前用户身份打开 HID。系统自己的音量处理可能和映射叠在一起，验收时要看音量是不是跳两格。

## 真机验收清单

在一台真的 Windows 和一只 A2854 上逐项勾。没勾的保持未验证。

- [ ] 蓝牙里能配对，程序日志出现 `VID=004C PID=0315`。
- [ ] 拔掉遥控器后，状态回到「没有打开的 A2854 HID 接口」，已按下的键会松开。
- [ ] 按返回、TV、播放/暂停、音量、静音、电源、方向和确定，日志有一次 down 和一次 up，并且只触发一次。
- [ ] 左方向有报告。若没有，记录原始十六进制；公开映射里的左键位可能和这只固件不一致。
- [ ] 按住 Siri 时，右 Ctrl 保持按下，松开后抬起。诊断里如果出现 Opus 计数，确认系统录音设备列表里仍然没有遥控器麦克风。
- [ ] 手指在圆盘上移动，光标跟随。若日志完全没有触控报告，指针不该动。这时记下原始报告，不要改成模拟移动。
- [ ] 轻点是单击。快速滑动触发对应手势，而不是单击。
- [ ] 按稳再挪时开始拖拽；只打开「按下后锁定指针」时，同样的按压不拖动光标。
- [ ] 沿外环转圈会滚动，刚放上去的一小段不滚动。方向不对就打开「反转滚动方向」。
- [ ] 给返回键配 0.5 秒长按，短按和长按走不同动作。
- [ ] 给某个程序单独映射，切到那个程序才生效；切回本程序时用全局映射。
- [ ] 退出再打开，映射还在。
- [ ] 电量数字会变；插上充电后，状态只有在读到约定字节或电量上升时才显示充电。
- [ ] 托盘图标能打开窗口，关闭窗口不会退出进程，托盘里的退出才会。
- [ ] 音量键没有被系统和程序各调一次。如果会，把音量映射改成「不执行操作」。
